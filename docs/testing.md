# Testing Strategy

Testing is a major component of this project and runs alongside development each sprint, not just at the end.

## 1. Tooling

| Test type | Tool |
|---|---|
| Unit | Pytest |
| Integration | Pytest |
| UI | Playwright |
| Regression | Pytest + Playwright (rerun existing suites) |
| Performance | Measured manually / scripted; documented only when actually run |

## 2. Unit Testing (Pytest)

Covers isolated logic, primarily in the packet parsing, database, and security detection modules:

- Packet parsing
- IP extraction
- Protocol identification (TCP/UDP/ICMP)
- Timestamp extraction
- Packet-size extraction
- Database operations (CRUD on `packets` and `security_alerts`)
- Security detection logic (port scan rule, abnormal traffic rule)

## 3. Integration Testing

Verifies the module-to-module flow works end-to-end:

```
Packet Capture → Parser → Database → Flask API → Dashboard
```

Focus areas: captured packets are correctly parsed and persisted; the API correctly reads back and filters stored data; alerts generated by detection logic are persisted and retrievable via the API.

## 4. UI Testing (Playwright)

- Dashboard loads successfully
- Packet table appears and displays data
- Search works
- TCP/UDP/ICMP filters work
- Navigation works
- Security alerts appear on the dashboard
- Buttons perform their expected actions

## 5. Regression Testing

After adding or changing any feature, rerun the existing Pytest and Playwright suites to confirm prior functionality still works. Playwright is also used for browser-based regression checks on the dashboard.

## 6. Performance Testing

To be evaluated later in the project (Sprint 5–6):

- Packets processed per second
- API response time
- CPU usage
- Memory usage
- Packet drops under load
- Database read/write performance

**Rule:** Only document results that have actually been measured. Do not write placeholder or estimated performance numbers into documentation or the final report.

## 7. Sprint 1 Testing Scope

For Sprint 1 specifically (Project Setup & Basic Capture), initial tests should cover:

- Pytest environment is correctly configured and runnable
- Basic packet capture returns packets from a live interface (smoke test / mockable)
- Source/destination IP extraction from a captured or sample packet
- Timestamp extraction
- SQLite `packets` table is created with the expected schema

Further protocol parsing, filtering, and security detection tests are added in later sprints as those features are implemented (see `sprint-plan.md`).
